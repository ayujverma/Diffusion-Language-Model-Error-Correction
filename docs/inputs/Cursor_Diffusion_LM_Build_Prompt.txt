1. THE QUESTION AND WHAT IS FIXED

Question: When training drafts are held fixed, does weighting incorrect tokens by their saved generation-time confidence improve correction beyond uniform weighting, generation-time correct-target difficulty, and current correction difficulty?

A draft is a model-generated response before correction. Define three distinct signals at an incorrect token position i:
- c_i: the frozen generator's probability of the actual wrong token it committed, in the partial context at the commitment event.
- q_i: that same generator distribution's probability of the correct target token at that same event. Generation-time correct-target difficulty is d_gen_i = -log(q_i).
- d_now_i: the CURRENT corrector's cross-entropy for the correct target token given the question and saved draft, recomputed during training.
These are different quantities measured at different times or with different contexts. c_i + q_i <= 1 for distinct wrong and correct tokens, so high c_i already implies some generation-time difficulty. Comparing c_i against d_gen_i is needed to test whether wrong-token confidence adds value beyond that older difficulty signal. No incorrect token has to be excluded: the rules allocate different loss weights across the same errors.

The contribution is a controlled replication and extension that isolates loss weighting on fixed inputs. Self-correction, confidence-based input selection, and token reweighting already exist. Do not claim we invented them, proved novelty, or will beat the baselines. Confidence-based selection that changes the model input is not equivalent to simply weighting a loss on fixed drafts.

Core experiment:
- Perform one common masked fine-tuning warmup.
- Freeze a copy of the resulting checkpoint for draft collection.
- Generate an immutable draft bank from training problems at several decoding budgets.
- Initialize each correction-training arm from the identical warmup checkpoint.
- Give the main weighting arms identical drafts, targets, example order, optimizer settings, trainable parameters, ordinary masking examples, and correction/preservation coefficients within each paired seed.
- Change only the error-weighting rule.
- Evaluate these arms with the same correction decoder and schedule, then assess sampler dependence separately.

Keep two comparison families distinct:
A. Causal comparison of weighting rules on identical saved drafts.
B. Adaptations of prior methods, which may create their own inputs and use their intended samplers.
Do not label a prior method as the shared-draft control when it changes input construction. Do not call our frozen-bank arm an exact reproduction of ProSeCo's online training.

Required arms:

7. EXACT LOSS AND WEIGHTING CONTRACT

For a correction example, let E be wrong editable response-token positions and K be already-correct editable positions. Exclude prompts and padding. Let ell_i = -log p_theta(correct_target_i | question, draft), using the aligned CURRENT correction logits.

Use:
L = L_mask + lambda * L_error + mu * L_keep
L_error = sum_{i in E}(w_i * ell_i) / number_of_errors
L_keep = mean_{i in K}(ell_i)

Use safe zero losses for empty sets; log how often each set is empty. Average over valid tokens within the declared loss minibatch, not padded sequence length. Define the ordinary masking branch separately. The main correction training step may use a masked-example forward pass plus a saved-draft correction forward pass; it does NOT regenerate the saved draft online.

Keep lambda, mu, masking data, sampling rates, batch shapes, optimizer and schedule identical across the main weighting arms. Define a small validation sweep later; report its budget. Choose and log initial lambda/mu, rather than suggesting they are values mandated by the papers.

Proposed rank weights:
- Group incorrect tokens by decoding budget AND saved generation mask fraction using predetermined bins, e.g. [0,.2), [.2,.4), [.4,.6), [.6,.8), [.8,1]. Retain exact step/block metadata for diagnostics. The same mask fraction under different budgets can arise from different reveal decisions. Keep grouping identical for all weighting rules and choose it before inspecting final outcomes.
- Pool tokens across the physical loss minibatch, not separately per response. Keep this minibatch definition fixed across arms. Gradient accumulation does not automatically make ranks equivalent to a larger physical batch.
- For n errors in a bin, use average ranks for ties, rank 1 through n. Set r_i=(rank_i-.5)/n.
- An initial bounded rule is w_raw=1+beta*(2*r_i-1), with beta=.5 giving [.5,1.5]. Normalize by the mean weight within the bin. Midranks have mean .5, so this rule already has mean-one weights up to numeric error. A singleton or fully tied bin gives weight 1.
- Assert bounds, finite values, within-bin mean one, and no gradients through weights. Log sparse/singleton bins; a run with no weight variation cannot test the hypothesis.
- If the pilot shows sparse groups, first use a fixed, stratified minibatch sampler shared across arms or coarsen bins using training/validation only. Bank-level percentiles are an alternative protocol, not a silent fallback: if used, document normalization and estimate the current-loss arm's reference scores on the same training bank at a fixed refresh interval, with its cost counted. Do not change one arm's ranking population without disclosing the mismatch.
- beta is configurable and selected on validation. beta=0 must recover the uniform implementation.

Controls use the same rank-to-weight rule and normalization:
- Uniform: w_i=1.
- High confidence: rank saved log_c upward.
- Generation-time correct-target difficulty: rank saved -log_q upward. This is a required baseline distinct from current correction difficulty.
- Low confidence: reverse those ranks.
- Shuffled confidence: deterministically permute saved scores among errors within the same budget/stage bins before ranking. Preserve the weight distribution; log how many scores actually move. Inspect confounding by task difficulty, value slot, and token class. If results track those factors, add a focused shuffle within adequately populated matched groups or report matched subgroup results. Do not create so many strata that every error becomes its own group.
- Hard example: rank CURRENT ell_i.detach() upward. Do not allow gradients through the weighting function; otherwise the objective has changed. Keep stage binning and weight range matched.

A high weight does not imply the largest final loss or parameter gradient. Log both weight and weighted CE. The example inspector must make this visible.

Mean-one weights fix total weight, not gradient norm or effective learning rate. Log group sizes, weight variance, effective sample size (sum w)^2 / sum(w^2), and occasional error-loss gradient norms using the same measurement schedule across arms. Keep the main optimizer settings equal; do not secretly rescale one arm's gradients to force a preferred result. If update-size differences explain a gain, evaluate a small validation-controlled learning-rate check and report its cost. Give arms comparable tuning budgets. Treat mu and lambda as parameters to validate, not guarantees that correct tokens will be preserved.
